# V33 WorkGraph: Counterfactual Labor as an Expiring Option

## Why V33 changes the research direction

V32 remains the strongest live control.  The recent adaptive variants taught a consistent lesson: we are better at diagnosing difficult games than at turning that diagnosis into reliable action changes.

That suggests a narrower question:

> Where does V32 make a structurally expensive decision that can be re-valued from the current public state without rewriting the farm plan?

The best candidate is labor.

V32 uses a fixed daily hand target.  Hands disappear at the end of the day while their hire price follows a Fibonacci curve.  A late marginal hand can therefore be extremely different from an early cheap hand even when both are generated by the same target schedule.

V33 treats each proposed HIRE as a short-dated financial option on the farm's visible work queue.

## Core architecture

```text
observation
   |
   v
exact V32-style farm controller
   |
   +------------------------------+
   |                              |
   v                              v
all normal actions          proposed HIRE actions
                                  |
                                  v
                         visible WorkGraph twin
                                  |
                     +------------+-------------+
                     |                          |
                     v                          v
              robust value >= cost       robust value < cost
                     |                          |
                     v                          v
                 keep V32                suppress HIRE only
```

Everything except marginal hiring remains on the V32 backbone:

- crop targets unchanged;
- animal targets unchanged;
- sell logic unchanged;
- feed purchases unchanged;
- land timing unchanged;
- farmer/hand routing unchanged;
- watering/feeding/harvesting priorities unchanged;
- terminal liquidation unchanged.

This gives V33 a very small blast radius.

## WorkGraph representation

The runtime model converts visible farm state into a queue of economically weighted service obligations.

Examples:

- planting-day WATER gets high critical weight because missing it can destroy a crop immediately;
- an already-dry crop is critical;
- FEED gets high critical weight because feed failure can remove future animal production;
- ripe crop/animal HARVEST receives value proportional to visible yield and product price;
- CARE and fertilizer collection receive smaller value;
- weeds and empty expansion tiles create bounded constructive-work demand;
- expected within-day task arrivals grow with productive tile and animal count.

The resulting state contains:

```text
backlog
weighted economic consequence
critical-service demand
existing labor capacity
marginal hand capacity
hours remaining before labor expires
```

## The novel model: an ephemeral labor option

For a proposed hand, V33 evaluates three structural scenarios rather than using a point estimate:

1. pessimistic travel/service efficiency;
2. neutral efficiency;
3. optimistic efficiency.

For each scenario:

```text
useful marginal tasks
    = min(residual work queue, marginal hand capacity)

hand value
    = useful marginal tasks * economic value per task
```

The controller then forms a lower-tail-biased value:

```text
robust_value = 0.55 * expected_value + 0.45 * worst_scenario_value
```

and compares it with the exact next Fibonacci hire cost.

A hand is not an asset.  It is an option that expires at midnight.  Saved cash, by contrast, retains option value for land, animals, seeds, feed, and future market decisions.

## Capital optionality

Around V32's two major expansion cliffs, V33 increases the hurdle for an expensive temporary hand because preserving liquid capital has extra option value.

This does **not** move or invent a land purchase.  It only asks whether an expiring unit of labor deserves to consume capital that may shortly fund a persistent productive asset.

## Hard safety exceptions

V33 does not suppress a hire if existing labor capacity cannot cover critical feed/water work.

It also preserves:

- every cheap hire with Fibonacci cost <= 34;
- the entire opening through day 4;
- the entire late game after day 18;
- late-night cleanup behavior;
- at most two suppressions per day.

These constraints intentionally bias V33 toward V32 parity.

## Why this is different from N3/N5/N6/N7

The recent experimental families mostly asked:

```text
Is this game dangerous?
Is this opponent a hard archetype?
Will the opponent sell soon?
```

Those signals can be statistically excellent while the induced action still has negative value.

V33 asks a different question:

```text
What is this exact V32 action worth right now?
```

It does not classify the opponent and then switch policy.  It prices one proposed action from the work it could actually perform before expiry.

## Why labor is a promising seam

The project has already observed rare but very large counterfactual regret around HIRE decisions.  Unconditional suppression is harmful, which means the action itself is not bad.  The missing object is the state-dependent marginal value of the *next* hand.

That is exactly what WorkGraph models.

The thesis is:

> V32 is usually correct about how much farm we want.  It may occasionally be wrong about how much expiring labor we should buy to service that farm at this particular hour and state.

## Evaluation plan

V33 should be compared directly with V32 using paired seeds and both seats.

Track more than win rate:

- paired win delta;
- paired final-cash delta;
- V32 HIRE proposals observed;
- V33 HIRE suppressions;
- suppression cost distribution;
- day/hour distribution of suppressions;
- critical-work safety exceptions;
- next-day cash difference;
- land/animal/seed purchase timing after a suppression;
- win -> loss flips;
- loss -> win flips;
- worst opponent-family delta.

The most important diagnostic is **policy value conditional on activation**.

## Promotion gate

V33 should not replace the V32 live control merely because the mechanism is elegant.

Recommended minimum gate:

```text
paired win delta vs V32             >= +0.015
hard-regime win delta               >= +0.03
safe-regime win delta               >= -0.005
worst-family delta                  >= -0.01
Q10 paired margin delta             >= 0
win -> loss flips                   <= loss -> win flips / 3
invalid games                       = 0
V32 parity when gate inactive       = 100%
```

Freeze all thresholds before the final confirmation set.

## If V33 works

Do **not** immediately turn WorkGraph into a giant planner.

The next extension should price one additional action family using the same principle, likely strawberry seed volume or land timing:

```text
V32 proposes action
       |
       v
state-specific structural valuation
       |
       v
change only if lower-tail value clears a strict hurdle
```

That would gradually convert V32 from a fixed macro tape into a conservative model-predictive controller while preserving every part of the champion that has not earned a reason to change.

## If V33 fails

A failure is still informative.

If suppressed hires save cash but reduce wins, then labor is doing more hidden coordination work than the visible queue captures.  The next model should learn missing task-arrival/service-capacity terms rather than broadening the action space.

If the gate almost never activates, the fixed hand schedule is already near-optimal and research should move to a different decision cliff.
